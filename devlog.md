### Invariants
- Invariants (apply to EVERY task — read first)
    - THE CODE IS THE SOURCE OF TRUTH: every code block in a must-source language (java/xml/yaml/sql/proto/ts/json/…) carries `source: '<repo-root-relative path>'` and passes the SnippetSourcesTest strict verification (ordered subsequence after comment/blank normalization; `// …` elisions + trailing teaching comments allowed; RATCHET = 0 — an unsourced must-source block FAILS the suite). New teaching = write the real implementation first, then quote it; only when no real counterpart exists may a compilable exhibit live in `domain/teaching/` and be quoted. Bash/command/output blocks are exempt. Never relabel a language to dodge the check.
    - Dependency rule: presentation → domain ← data. Controllers never import the data layer; DTOs never leak past adapters. Documented exemption: teaching-exhibit controllers may import data/ directly (marked teaching-exception).
    - Thin controllers: parse/validate input → call a use case → map Result to an HTTP response. No business logic in controllers.
    - One error taxonomy end-to-end: typed exceptions → @ControllerAdvice global handler → failure types → one consistent HTTP error envelope. Nothing swallowed; every failure logged with a request ID.
    - DI at the composition root: config/ @Configuration wires ports to adapters; fake/live wiring switchable at runtime for demos (ScenarioStore, PATCH /api/demo/scenario).
    - Teaching anatomy: each concept section teaches → text → sourced code → ITS live demo INLINE beside it (never queued at page end); every topic closes with a terminal-companion section (text + curl tour, bash blocks). No screen ships with only a CodeBlock.
    - Content depth (developer mandate, 2026-10-06): comprehensive coverage — every topic taught in detail: concept-first explanations, real examples, working demos; target depth = express guide's per-topic median (~3k words).
    - Guide-family consistency: reuse the react guide's design tokens and screen anatomy; the express client is the reference implementation for content-driven screens; theme DARK default, key 'sdg-theme'.
